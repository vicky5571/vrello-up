# 2026-09-29

## Outlets table scroll/layout audit (read-only, no code changes)

Deliverable: `docs/audit-outlets-table-scroll.md`

Root cause found: `OutletsView.tsx:441` root is `<div className="space-y-4">` — a block box with
`height: auto` inside the definite-height `motion.div.h-full.w-full` (page.tsx:309). Every
descendant percentage height therefore collapses to `auto`, so `MarcomTableShell`'s
`h-full overflow-y-auto` (Shell:282) is inert. Overflow escapes to `page.tsx:203`
(`flex-1 overflow-hidden`) and is silently clipped — pagination + trailing rows unreachable.

Contrast: `BranchesView.tsx:291-293` renders `<MarcomTableShell>` with no wrapper div, so the
same shell works there. The regression came from adding the view-mode switcher header.

Other findings:
- Shell:389 `overflow-x-auto` → `overflow-y` computes to `auto` (CSS Overflow L3) → the card is a
  dual-axis scrollport, so `sticky top-0` on the header row (Shell:392) would never activate.
  Header row also has no sticky at all and uses a translucent bg (`bg-slate-50/70`).
- Table intrinsic min-width = 1316px → horizontal scroll is the default state, and the h-scrollbar
  sits below the whole row body.
- Zero `overscroll-behavior` in the entire `src/` tree.
- `parseOutletSearchLimit` hard-caps `take` at 100 and `fetchOutlets` never passes `q`/`limit`, so
  the view paginates a 100-row sample while claiming counts over a ~25k dataset.

Recommended remediation (P0): flex budget chain
`OutletsView` root → `flex h-full min-h-0 flex-col gap-4 p-4 md:p-6`, switcher header `shrink-0`,
shell `noPadding className="flex-1 min-h-0"`; shell becomes `flex h-full min-h-0 flex-col` with
chrome as `shrink-0` siblings and the table card as the single
`flex-1 min-h-0 overflow-auto overscroll-contain` dual-axis scrollport with a
`sticky top-0 z-20` opaque header. Then server-side pagination; defer virtualization (YAGNI).
